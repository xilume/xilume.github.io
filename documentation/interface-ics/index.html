Protocol capabilities

The current protocol supports Classical CAN and CAN FD data frames with BRS. RTR remote frames are not represented; extended frames with numeric IDs at or below 0x7FF cannot be distinguished from standard frames, and ESI is not encoded in the receive format. Channels share the USB Full-Speed link; validate aggregate throughput under the intended workload.

Design review

  1. Check the device and pin orientation

    Use the corresponding top-view pin diagram, then check power connections, reserved-pin bias and NC-pin handling.

  2. Check the clock and transceivers

    Both datasheets specify an 8.000 MHz main clock. Select external transceivers for each channel’s voltage and data-rate requirements.

  3. Review layout and assembly

    Check USB differential routing, decoupling and reference planes against the datasheet. Package drawings define geometry; confirm PCB land patterns and stencil dimensions with the assembly process.

  4. Validate the complete system

    Exercise concurrent channels, USB reconnection, host reboot and power recovery, then validate temperature, interference and termination for the application.
