# 快捷联系表单维护

日期：2026-09-25

## 目的与页面

让首次询价、选型和技术问题可直接在网页提交。中英文页面为 `contact/index.html` 与 `zh-cn/contact/index.html`，共用 `contact/contact.css`、`contact/contact.js`。保留既有导航、Logo、SEO 和资源链接；不改动产品事实和价格。

邮箱、问题必填；姓名选填；咨询类型默认价格，可选选型、支持或其他。无需账户、公司名称、电话、完整项目介绍或附件。“一个工作日内回复”来自用户明确要求，不是实现者推定。实际履约由工作人员处理业务邮箱。

设计参考 [Linear 联系页](https://linear.app/contact) 的目的清晰和紧凑入口、[Stripe 销售联系页](https://stripe.com/en-ca/contact/sales) 的表单层级与回复预期，采用 Xilume 现有蓝色和品牌素材创作。没有复制对方品牌、插图或较长的企业信息收集流程。

## 收件与数据

- 唯一目的地址：`contact@xilume.co`；不设置私人地址、CC 或 BCC
- 原生 POST：`https://formsubmit.co/contact@xilume.co`
- 使用原生表单导航；不再调用 AJAX 接口，因为它不支持自动确认邮件
- 表单值：`email`、`name`、`message`、`topic`；隐藏字段包含语言、固定公开来源页、主题、table 模板、验证码开关、用户提供的确认文案和蜜罐
- `email` 作为可回复地址；没有客户端密钥、邮件密码或 SMTP 凭据
- 仅在提交时发送；不把输入存进 localStorage、日志、分析事件或仓库；提交 payload 与固定 `_url` 不携带访问 URL 的 query/hash。浏览器自行发送的 Referer 头不属于离线测试已验证的字段
- 页面说明通过 FormSubmit 发送并链接其 [隐私政策](https://formsubmit.co/privacy.pdf)

按 [FormSubmit 文档](https://formsubmit.co/documentation) 和 [帮助](https://formsubmit.co/help)，首次需要收件人激活；未激活提交保留 30 天，激活后补投，服务亦提供 30 天提交归档。不要宣称服务不存储。AJAX 不支持自动回复；网页显示成功不等于自动给客户发送确认邮件。

明确设置 `_captcha=true` 和 `_autoresponse`。中英文页面均使用用户在 2026-09-25 提供的英文确认文案，段落换行通过 HTML 字符引用保存在隐藏字段里；移除粘贴时的 Markdown 反斜线与链接语法，保留邮件内容。确认邮件由 FormSubmit 服务生成，不能声称由 Dynadot 发出或自定义了服务端 From/Subject。客户确认邮件的实际 Reply-To 与收件仍需真实邮件验证；供应商文档没有单独的 autoresponse Reply-To 设置。

## 交互与验证

2026-09-25 改为浏览器原生 POST，保留邮箱/问题校验、空白修整和蜜罐拦截。有效表单不调用 preventDefault，不 fetch，不清空输入，不提前显示成功，也不自动重试；浏览器打开服务商页面完成验证码与提交，供应商处理后显示提交结果。无 JavaScript 时使用相同原生表单和隐藏配置。没有实现自定义成功页或恢复旧 AJAX 流程。

`node scripts/test-contact-form.cjs` 执行完整脚本的离线最小 DOM 测试，当前 8 个场景覆盖中英文原生提交、自动回复/验证码参数、必填与空白校验、蜜罐、可选姓名、内容保留、不支持 fetch 的环境和来源 URL 隐私。旧 AJAX 响应/超时测试随 AJAX 实现移除。离线测试不发送邮件，不能证明实际收件。

每次相关改动检查中英文、键盘与提交方式。两页 Contact JS 版本为 `20260925-autoreply1`，CSS 版本保持。最新浏览器/部署验证状态见 STATUS。

## 2026-09-08 历史验证（旧 AJAX 实现）

2026-09-08 首次脚本请求遭服务 Cloudflare 403；未在该路径重复请求。正常浏览器的本地预览表单提交进入待激活分支，用户随后确认已激活；之后本地中文真实表单显示服务已接受，字段清空、按钮恢复且控制台无错误。正式来源随后另经激活，并在官网实际提交显示已被服务接受。没有读取私人邮件内容或验证邮箱转发规则。实际 inbox 投递、跨浏览器、无 JS 托管页和验证码挑战不在此已验证结论内。发布和线上实际提交以 STATUS 最新记录为准。

## 后续故障处理

首次上线需在真实正式域名验证激活状态：本次本地来源在用户激活后可以提交，但 `https://xilume.co/contact/` 的首次实际提交仍返回激活提示；用户确认最新官网来源激活后，正式站真实提交成功。不要把隐藏 `_url` 设置为正式地址或本地预览成功，当作正式站来源已启用的证据。

先区分页面未加载、输入校验、请求未确认、服务未激活、服务已接受但业务邮箱未收到、工作人员尚未回复。不要把浏览器成功提示等同所有环节成功。收件地址或供应商改变时重新验证激活和真实提交，不擅自改私人邮箱作为备用收件人。API 响应格式变化时保守失败并保留用户输入；避免从供应商响应渲染 HTML。服务中断期间保留可点击邮件和电话入口。
