Octant 与 XE826

连接硬件，安装驱动，确认通道并完成首次通信

硬件连接

产品主机连接现场接口
OctantUSB 外接主机2 × CAN FD · 4 × RS-485 · 2 × RS-232
XE826USB 内接主机2 × CAN FD · 4 × RS-485 · 2 × RS-232
  1. 连接主机

    Octant 使用配套 USB 连接线；XE826 在主机断电后安装固定，使用匹配的内接 USB 线束

  2. 核对线束与接口

    按照产品和配套线束的端口标识连接目标设备，CAN、RS-485 与 RS-232 使用各自对应的端口

  3. 设置通信参数

    CAN 的仲裁速率、数据速率与 FD/BRS 设置应与对端一致；串口的波特率、数据位、校验与停止位应与目标设备一致

Windows

  1. 先安装驱动

    下载下方对应驱动包并完整解压，在 Windows 文件夹运行 Xilume_Octant_XE826_Windows_Driver_V7.1.9.0.exe

  2. 连接设备并检查识别

    安装后连接设备，在设备管理器的“端口”中确认两个 CAN FD COM 端点与六个串行 COM 端口，COM 编号由系统分配

  3. 打开 CAN FD 软件

    在熙联迈 CAN FD 控制中心中选择对应的 CAN 通道，设置通信参数后连接；需要记录和分析时可使用 TraceBox Analyzer Pro 英文版

CAN FD 的 COM 端点承载熙联迈 CAN 命令协议，使用 CAN FD 控制中心或按协议开发的应用完成收发

Linux

驱动包要求 Linux 5.4 或更新内核，支持 x86-64 与 aarch64；需要 DKMS、编译工具及与当前运行内核匹配的头文件

完整解压驱动包，在其中的 Linux 文件夹打开终端

chmod +x install.sh uninstall.sh verify.sh
sudo ./install.sh

安装完成后重新连接设备，再运行检查

./verify.sh

以检查结果中显示的实际 CAN 接口名为准，系统不保证始终分配 can0 与 can1

串口可通过 /dev/xilume/serial1 至 /dev/xilume/serial6 六个路径访问

安装时需要重启或无法找到内核头文件

如安装程序因 Secure Boot 提示导入本机密钥，请按程序说明完成重启与登记，再运行安装程序；定制内核需要由系统供应方提供匹配头文件，可通过 uname -r 确认当前版本

首次 CAN 通信

以下示例用于已正确接线的测试总线，假设检查结果显示目标接口为 can0；请替换为实际接口名，并将速率与对端保持一致

经典 CAN · 500 kbit/s

sudo ip link set can0 down
sudo ip link set can0 type can bitrate 500000
sudo ip link set can0 up
ip -details -statistics link show can0

安装系统提供的 can-utils 后，可在终端查看收到的数据

candump can0

CAN FD · 500 kbit/s + 5 Mbit/s

确认对端支持并使用相同的 CAN FD 速率，再切换到数据阶段配置

sudo ip link set can0 down
sudo ip link set can0 type can bitrate 500000 dbitrate 5000000 fd on
sudo ip link set can0 up

更高数据速率需要同时满足收发器、布线长度、终端和对端配置条件；8 Mbit/s 是 CAN FD 数据阶段速率

串口使用

Windows 使用设备管理器中标有 Serial 的六个 COM 端口，Linux 使用六个 serial 路径；将应用中的逻辑通道与实物端口逐一对应后，再连接目标设备

项目设置
接口4 × RS-485 · 2 × RS-232
应用设置波特率、数据位、校验、停止位与对端一致
通道映射以设备标识与驱动检查结果为准

接口与兼容性

平台当前驱动与接口

CAN 协议经典 CAN 数据帧、CAN FD 数据帧与 BRS

当前 CAN 文本协议不表示 RTR 远程帧，也不能区分数值不高于 0x7FF 的扩展帧与标准帧；选择目标协议或开发接口时请核对这一条件

识别与通信检查

现象检查方法
未发现设备先检查主机 USB 通道、供电和连接；Linux 使用 lsusb 查看 USB 识别
已识别但无 CAN 接口在驱动包 Linux 文件夹运行 ./verify.sh，保存实际输出和内核版本
有通道但无接收核对 CANH/CANL、总线末端终端、参考地以及双方速率和帧模式
重启后通道名称变化按检查结果重新映射实际接口名，避免在应用中直接假定 can0/can1 或固定 COM 编号
